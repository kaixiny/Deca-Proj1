# 自动化发布小红书笔记(含配图自动生成)

一、全局原则（贯穿整个任务）

1. 不保存登录态到磁盘：任务结束后不写 storage_state、不导出 cookie。但任务开始时使用浏览器默认 storage，不强制清除——OS-level cookie 自然继承是允许的。

2. 不写凭据：日志、代码、汇报中不出现账号、密码、token、cookie 值。

3. 少快照：默认禁止 browser_snapshot 和 browser_take_screenshot，除非在该步骤有允许。验证状态优先用 browser_evaluate。

4. 失败即停：单步重试 ≤ 2 次，仍失败则立即报告失败的阶段和现象，等用户指示。禁止"我换个方法再试试"——除非本文档明确给出了 fallback。

5. **小红书特殊原则——人化节奏**:
   - 操作之间适当停顿(1-2 秒),不要连续快速点击
   - 模仿人类行为(先观察页面再操作)
   - 如果遇到任何风控提示(滑块、二次验证、"操作过快"),立即停下来告诉用户

6. **遇到反爬立即停止**:
   - 出现滑块/极验 → 停下来,让用户手动完成
   - 出现"操作异常"提示 → 停下来报告
   - 任何风控警告 → 停下来,不要绕过


==== 小红书创作平台已知 DOM 结构(勿重复探索)====

**发布/草稿按钮区**:
- 容器是固定在视口底部的自定义元素 `<xhs-publish-btn>`
- 该元素通过属性暴露两个方法:
  - `_onSave()` → 暂存离开(保存草稿)
  - `_onPublish()` → 立即发布
- 调用方式:`document.querySelector('xhs-publish-btn')._onPublish()`
- 无需滚动、无需截图找按钮、无需 text= 选择器

**标题字数限制**:
- 小红书标题上限 20 字(中文、标点各算 1 字,emoji 算 2 字)
- 填写前必须先数字数;超出则先浓缩,再填入

**图片上传**:
- 小红书 file chooser 支持多选,一次性选择全部图片即可
- 无需逐张上传

二、调用时需要的输入
  用户调用时应一次性提供：

    文章路径（.md）
    配图路径列表（如已有）；未提供时本 skill 会生成
    配图保存目录（默认 final_reports/images/xiaohongshu-images/）

  如果用户的第一条消息已经包含这些信息，直接执行，不要再问。如果缺，只问一次，把缺的项放一起问。




==== 任务流程 ====

## Step 1 生成配图

首先询问用户：
- 需要发布的文章文件路径
- 配图文件路径列表(如已有)。如未提供配图,本 skill 会自动生成
- 配图保存目录(未提供时默认为文章同级目录下的 images/)

如果用户提供了配图，直接进入 STEP 2。

如果没有，开始生成配图：

1.1 技术选型自由度
  每张图用什么技术（HTML/CSS、SVG、Mermaid 等）你自己判断，原则：
  - 重视觉排版（如知识卡片）→ HTML/CSS 通常更合适
  - 重数据精度（如时间线、对比图）→ SVG 通常更合适
  - 不确定时默认 HTML/CSS
  - 最终都用 Playwright 截图为 PNG 输出
  - 一定要自己记住每个图应该放在哪里，方法你自己判断

1.2 配图分布的硬性要求

  - 空间均衡：分散到不同章节，避免 70% 以上集中在一节。必须有且只有一张封面图。
  - 内容多样：每张图主题不同，建议覆盖维度——背景介绍 / 历史时间线 / 关键数据 / 对比分析 / 总结洞察。
  - 叙事配合：图落在"读者需要视觉帮助理解"的位置——复杂数据/对比、历史叙事、转折点、总结性观点。避开纯过渡段、纯陈述段。

1.3 产品规格
  - 尺寸：
    - 小红书封面（xhs_cover_*）：1242 × 1660
    - 小红书内容图（xhs_card_*）：1242 × 1242
  - 配色：极简黑白 + 橙红 #FF6B35 强调色
  - 字体：Inter（英数）+ PingFang SC / Microsoft YaHei（中文）
  - 留白充足、关键数字大字突出
  - 文案风格：简洁易懂，避免工程化术语（比如用"全球远程"而非"分布式"）
  - 右下角小字水印"DECA × 聚锋"
  - 数据来源在底部小字标注（如果有具体来源）

1.4 产出
  - 保存图片，记录每张图应插入的章节位置（哪段文字之后），传给 STEP 2 使用


## STEP 2 自动推送

2.1 打开登录页 + 自动检测
  打开小红书创作服务平台（https://creator.xiaohongshu.com/）

  设置浏览器视口为全屏（保证表单完整可见）。

    **先用 `browser_evaluate` 检查当前 URL 是否已跳转到 xiaohongshu.com**：
    - 若已跳转（session 有效）→ 直接进入2.2。
    - 若停在登录页 → 输出人工操作提示，等我回复"已登录"才能继续。

        人工操作提示格式：

          ============================================
          [人工操作环节]
          请在浏览器中完成以下操作：
          1. 输入账号和密码
          2. 完成滑块/极验等人机验证
          3. 如有短信验证码，请完成
          4. 确认看到 小红书 首页（出现你的头像）
          完成后请回复"已登录"
          ============================================

2.2 进入发布笔记页面

  点击首页的"发布图文笔记"入口（ref 可从 snapshot 获取）。

  进入图文笔记发布页后，**仅取一次 snapshot 确认以下元素存在**：
  - 图片上传区
  - 标题输入框
  - 正文输入框

2.3 上传图片

  页面进入后通常会自动弹出 file chooser，若未弹出则点击上传区触发。

  **一次性**选择全部图片（第一张为封面）

  若上传失败 >2 次，停下来报告。

2.4 填入标题  

  定位标题输入框，填入阶段 1 已确认的标题（若超 20 字使用浓缩版）。

  填入后用 evaluate 读取字数计数器，确认格式为"X / 20"且 X ≤ 20。

2.5 填入正文+标签

  小红书标签的领域知识：
  - 标签输入框是 combobox（输入框 + 下拉建议）
  - 纯输入文字 #xxx 不算激活标签——必须从下拉建议点选，点击第一行的
  - 已激活的标签变成 chip 样式（蓝色胶囊），未激活的只是普通文字
  - 如果发现点选后仍然未激活，删除这个tag，重新进入输入激活流程
  - 处理流程：输入触发 → 等待出现下拉菜单 → 从列表点选第一个 → 验证 chip 样式 → 如果未激活就删除当先tag重新进入输入触发阶段


  正文内容来自 xiaohongshu_post.md，填写时：
  - 去除所有 `![...](images/xxx.png)` 图片引用行
  - 去除所有 `---` 分隔线
  - 去除所有 `**...**` markdown 加粗符号（保留文字内容）
  - 标签统一写在正文末尾空一行后

  填入后用 `snapshot(target=正文textbox的ref)` 确认内容段落结构正确。

2.6 发布笔记

  直接调用：

  ```javascript
  document.querySelector('xhs-publish-btn')._onPublish()

  严格禁止：调用后禁止执行任何额外的 evaluate、snapshot 或其他工具调用。
  调用成功即视为发布完成，直接进入 STEP 3。

## STEP 3 关闭与汇报

  关闭浏览器（若弹出"确认离开"对话框，点击确定）。

  给我完整的执行总结：
  - 每个阶段的实际操作摘要
  - 上传成功的图片数量
  - 遇到的所有问题和处理方式
