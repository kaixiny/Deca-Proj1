# 自动化发布 B 站专栏(含配图自动生成)


一、全局原则（贯穿整个任务）

1. 不保存登录态到磁盘：任务结束后不写 storage_state、不导出 cookie。但任务开始时使用浏览器默认 storage，不强制清除——OS-level cookie 自然继承是允许的。
2. 不写凭据：日志、代码、汇报中不出现账号、密码、token、cookie 值。
3. 少快照：默认禁止 browser_snapshot 和 browser_take_screenshot，除非在该步骤有允许。验证状态优先用 browser_evaluate。
4. 失败即停：单步重试 ≤ 2 次，仍失败则立即报告失败的阶段和现象，等用户指示。禁止"我换个方法再试试"——除非本文档明确给出了 fallback。

二、调用时需要的输入
  用户调用时应一次性提供：

    文章路径（.md）
    配图路径列表（如已有）；未提供时本 skill 会生成
    配图保存目录（默认 final_reports/images/bilibili-images/）

  如果用户的第一条消息已经包含这些信息，直接执行，不要再问。如果缺，只问一次，把缺的项放一起问。


==== 任务流程 ====

## Step 1 生成配图

首先询问用户：
- 需要发布的文章文件路径
- 配图文件路径列表(如已有)。如未提供配图,本 skill 会自动生成
- 配图保存目录(未提供时默认为文章同级目录下的 images/)

如果用户提供了配图，直接进入 STEP 2。

如果没有，开始生成配图：

1.1 技术选型自由度
  每张图用什么技术（HTML/CSS、SVG、Mermaid 等）你自己判断，原则：
  - 重视觉排版（如知识卡片）→ HTML/CSS 通常更合适
  - 重数据精度（如时间线、对比图）→ SVG 通常更合适
  - 不确定时默认 HTML/CSS
  - 最终都用 Playwright 截图为 PNG 输出
  - 一定要自己记住每个图应该放在哪里，方法你自己判断

1.2 配图分布的硬性要求

  - 空间均衡：分散到不同章节，避免 70% 以上集中在一节。必须有且只有一张封面图。
  - 内容多样：每张图主题不同，建议覆盖维度——背景介绍 / 历史时间线 / 关键数据 / 对比分析 / 总结洞察。
  - 叙事配合：图落在"读者需要视觉帮助理解"的位置——复杂数据/对比、历史叙事、转折点、总结性观点。避开纯过渡段、纯陈述段。

1.3 产品规格
  - 尺寸：1920 × 1080
  - 配色：极简黑白 + 橙红 #FF6B35 强调色
  - 字体：Inter（英数）+ PingFang SC / Microsoft YaHei（中文）
  - 留白充足、关键数字大字突出
  - 文案风格：简洁易懂，避免工程化术语（比如用"全球远程"而非"分布式"）
  - 右下角小字水印"DECA × 聚锋"
  - 数据来源在底部小字标注（如果有具体来源）

1.4 产出
  - 保存图片，记录每张图应插入的章节位置（哪段文字之后），传给 STEP 2 使用


## STEP 2 自动推送

2.1 打开登录页 + 自动检测
  打开 B 站登录页（https://passport.bilibili.com/login）。

  设置浏览器视口为全屏（保证表单完整可见）。

    **先用 `browser_evaluate` 检查当前 URL 是否已跳转到 bilibili.com**：
    - 若已跳转（session 有效）→ 直接进入2.2。
    - 若停在登录页 → 输出人工操作提示，等我回复"已登录"才能继续。

        人工操作提示格式：

          ============================================
          [人工操作环节]
          请在浏览器中完成以下操作：
          1. 输入账号和密码
          2. 完成滑块/极验等人机验证
          3. 如有短信验证码，请完成
          4. 确认看到 B 站首页（顶部出现你的头像）
          完成后请回复"已登录"
          ============================================

2.2 填写专栏

  访问 B 站专栏发布页。可以试 https://member.bilibili.com/platform/upload/text/edit，也可以从创作中心进入——以能稳定打开编辑器为准。

  **编辑器类型探测（仅做一次 `browser_snapshot`）**：
  取一次快照后即可判断编辑器结构，后续不再取快照。

  观察编辑器的实际形态（富文本？支持 markdown 粘贴？有导入按钮？），自己选择最合适的方式填入：
  - 标题
  - 正文（如果有图片占位符先跳过，下一阶段统一处理）

  如果编辑器形态出乎意料、或某种填入方式失败，停下来告诉我具体情况，等我决定。

2.3 标题层级校正（一次 evaluate 批量做）

  无论用哪种方案填入主体内容，文字粘贴后**所有段落很可能默认是正文级别**，必须手动校正。

  按文章的 markdown 标记对应设置。如果没有，请自己判断：
  - markdown 的 `# 一级标题` → 编辑器设为 H1
  - markdown 的 `## 二级标题` → 编辑器设为 H2
  - markdown 的 `### 三级标题` → 编辑器设为 H3

  对每个标题段：
  1. 用编辑器的鼠标选中操作（或键盘）选中该段文字
  2. 点击工具栏的样式，选择对应层级（<eva3-toolbar-head class="eva3-toolbar-item">，是一个可点击的下拉菜单button，可以选择H1,H2,H3还是正文）
  
  验证：所有标题层级矫正完成后，仅用一次快照检查标题是否矫正成功。

2.4 插入配图

  对每张图：
  - 定位到对应段落
  - 用编辑器提供的图片插入功能上传该 PNG
  - 确认图片成功上传后再处理下一张（最好用evaluate）

  如果某张图反复失败（>2 次），停下来报告问题，不要静默跳过。

2.5 上传封面
  找到上传封面位置，上传。如果封面大于 B 站要求尺寸，会弹出裁剪窗口，只要点击确认即可。

## STEP 3 发布专栏

找到"发布"功能（有个"发布"的button）。

点击按钮后，可能会出现两种弹窗：
  1. 显示“你的专栏已提交成功”，直接进入STEP 4。
  2.弹出验证窗口，输出人工操作提示，等我回复"已完成"。

    人工操作提示格式：

      ============================================
      [人工操作环节]
      请在浏览器中完成以下操作：
      1. 完成滑块/极验等人机验证
      完成后请回复"已完成"
      ============================================

    然后停止所有工具调用，等待我回复。回复后可进入阶段 9。


## STEP 4 清理与汇报

  4.1 关闭浏览器。
    注意：若弹出"确认离开"对话框（B 站会因发布后页面被视为有未保存编辑而提示），点击"确定"。

  4.2 给我完整的执行总结汇报，包括：
  - 每个阶段的实际操作摘要（你具体怎么做的、用了哪些工具）
  - 上传成功的图片数量
  - 遇到的所有问题和你的处理方式
